# Контрольные вопросы: «Работа с файлами в PHP»

## 1. Зачем добавлять папку PHP в переменную PATH и как проверить, что PHP установлен?

Переменная `PATH` позволяет запускать команду `php` из любой папки CMD без указания полного пути к `php.exe`. Установку проверяют командой `php -v` (выводит версию PHP), а путь к активному файлу конфигурации — командой `php --ini`.

## 2. Какой командой запускается встроенный сервер PHP и как указать другой порт или корневую папку?

В папке проекта выполняют `php -S localhost:8000`. Для другого порта — `php -S localhost:8080`. Корневую папку можно указать параметром `-t`: `php -S localhost:8000 -t C:\projects\filemanager`. Если нужен конкретный конфигурационный файл: `php -c php.ini -S localhost:8000`.

## 3. Почему форма загрузки не работает без `enctype="multipart/form-data"`?

Этот тип кодирования нужен, чтобы браузер передавал содержимое файлов в теле POST-запроса. При стандартном кодировании `application/x-www-form-urlencoded` содержимое выбранного файла не передаётся как загруженный файл, поэтому массив `$_FILES` не содержит ожидаемых данных.

## 4. Какие ключи содержит массив `$_FILES['userfile']` и что хранится в `tmp_name`?

Обычно: `name` — исходное имя, `type` — MIME-тип, присланный браузером (ему нельзя слепо доверять), `tmp_name` — путь к временному файлу на сервере, `error` — код ошибки, `size` — размер в байтах. В современных версиях также встречается `full_path`, если браузер передаёт относительный путь. Временный файл нужно перенести до окончания скрипта.

## 5. Чем `move_uploaded_file()` отличается от `copy()`?

`move_uploaded_file()` проверяет, что указанный источник действительно является файлом, полученным через HTTP-загрузку PHP, и переносит его в целевой каталог. `copy()` лишь копирует произвольный файл, не проверяя его происхождение. Поэтому при обработке `$_FILES` следует применять `move_uploaded_file()`.

## 6. Чем отличаются `upload_max_filesize` и `post_max_size`? Какое значение должно быть больше и почему?

`upload_max_filesize` ограничивает размер **одного файла**, а `post_max_size` — размер **всего POST-запроса**, включая файлы и другие поля. `post_max_size` должно быть больше `upload_max_filesize`, поскольку запрос содержит дополнительные служебные данные. При множественной загрузке размер всех файлов также должен укладываться в `post_max_size`.

## 7. Что произойдёт с массивами `$_POST` и `$_FILES`, если запрос больше `post_max_size`?

PHP не обработает тело POST-запроса обычным образом, поэтому `$_POST` и `$_FILES` станут пустыми. PHP может записать предупреждение о превышении лимита. Программа может обнаружить ситуацию, сравнив `$_SERVER['CONTENT_LENGTH']` с размером `post_max_size` в байтах, и показать понятное сообщение об ошибке.

## 8. Почему `upload_max_filesize` нельзя изменить через `ini_set()`?

PHP применяет настройки загрузки до выполнения скрипта, во время приёма и разбора запроса. Изменение этого параметра уже после начала работы скрипта не повлияет на принятую загрузку. Его задают в `php.ini` или аргументом `-d upload_max_filesize=...` при запуске сервера.

## 9. Для чего при удалении и сохранении файлов используется `basename()`?

`basename()` удаляет компоненты пути, оставляя только имя файла. Это помогает предотвращать выход из каталога `uploads` через последовательности вроде `../` при удалении и загрузке. Но одной этой функции недостаточно: дополнительно проверяют допустимое расширение, очищают имя и убеждаются, что целевой путь находится в нужной папке.

## 10. Почему нельзя разрешать загрузку файлов с расширением `.php`?

Потому что веб-сервер может выполнить загруженный PHP-файл как программный код, а не просто отдать его для скачивания. Это создаёт риск удалённого выполнения произвольных команд и компрометации сайта. Поэтому приложение разрешает только определённые безопасные для учебного задания расширения и не принимает `.php`.
